# Module:Dependencies

The dependency notices on module and template pages: the modules, data and stylesheets a page uses, and which pages use it.

Module:Documentation shows them on every documented module and template, and [MediaWiki:Scribunto-doc-page-does-not-exist](https://starcitizen.tools/MediaWiki:Scribunto-doc-page-does-not-exist) on a module with no `/doc`.

## For module editors

### API

Each page's row lives in the `dependencies` table of [Extension:Bucket](https://www.mediawiki.org/wiki/Extension:Bucket), schema `Bucket:Dependencies`, generated by `mise run bucket:schemas` from `properties.json`, registered in `Module:BucketQuery/manifests.json`.

- `_main(pageName, addCategories) → string`: the notices for `pageName` (default: the current page, or the page a `/doc` documents). `addCategories` defaults to true except on a `/doc` render.
- `main(frame)`: the same for the current page, as `{{#invoke:Dependencies|main}}`.
- When `addCategories` is true, adds `[[Category:Lua-based templates]]` to a template with at least one invoke, `[[Category:Strict mode modules]]` to a module that requires `strict`, and `[[Category:Unused modules]]` to a module nothing invokes, requires, or loads.

### Gotchas

- A page writes its row only while rendering itself: never from its `/doc`, or a title containing `/sandbox` or `/testcases`, or starting with `Sandbox/`, in either namespace. A module's "used by" lists read other pages' rows when the module's own page renders, so a new dependent appears after that page is next re-parsed.
- Only literal module names are stored. A dynamic `require('Module:X/' .. name)` is shown as `Module:X/…` and stored nowhere.
- A template that never shows `{{Documentation}}` writes no row, so the modules it invokes do not list it; a module whose `/doc` never shows it writes no row either.
- Stylesheet pages show no notices, so a stylesheet's users are listed on the page that owns it: `Module:Icon` lists who loads `Module:Icon/styles.css`. Only a `/styles.css` subpage has an owner.
