# commlinks

Plans the pages of one RSI Comm-Link series that the wiki is missing; `config.json` configures the monthly reports. See [`../../README.md`](../../README.md) for how tools run; this file covers what this one decides and why.

## What it plans

- **Discovery** is RSI's own series listing (`series` in `config.json`) plus the Star Citizen Wiki API's title search (`titleQuery`, kept when `titlePattern` matches). Neither source is complete on its own: a report that either source finds is a candidate, and `plan.json` lists under `discoveryDisagreements` every report only one source found. When the API answers 404 for a report only the series lists, the API has no record of it yet, and the report goes to review rather than stopping the run; a series listing with no reports stops it. A candidate is missing when no page's `{{CommLink}}` `url` carries its RSI number (the `comm_link` Bucket table).
- **Body text** comes from RSI's HTML: the classic layout to October 2021, and from then a Vue shell whose body is a separate fragment named by `const s3Url`. The API's plain text is only the check: every API line must appear in the generated page, and the API text must have at least half the words of the page body (file lines and template calls left out), since an API text the API has not finished scraping checks only part of the page. `apiTextAccepted` lists reports a person has read against RSI's page, which pass the word check. Two API artefacts pass on their own: a line the API glues across page blocks in page order (a paragraph run into the sign-off past the Conclusion title and an image), and a line made up only of pieces of the page's image captions (a credit's intro such as "Image by" and a name), which the API runs together without spaces. `fidelityIgnore` lists the other accepted API lines.
- **Headings** are RSI's own, plus a bold line standing alone before more text, which becomes a subsection heading one level below the section's. A bold line is never a heading when it holds a colon (an addressee line such as `TO: SQUADRON 42 RECRUITS`), belongs to an emphasis article (the bold closing block of a fragment report), or matches `greetingPattern` or `signOffPattern`. The same two patterns turn a classic intro heading (an `h1`, or a heading inside `variant-block`) into bold text, and in a fragment report `signOffPattern` does so for the sign-off heading and every later heading of its article. A classic page's first title block is the page title, not a section, when it matches the report's title or `titlePattern`.
- **Dates** come, in order, from RSI's series listing, whose `Posted:` value is the publication time for older items (`dateSource: "rsi"`; recent items show only an age such as "3 weeks ago"); else the API's `created_at`, unless it is one of `apiIngestDates` (days the API imported reports in bulk) or later than the first Wayback Machine capture of the RSI page (`"api"`); else that capture's UTC day (`"wayback"`). RSI's own `Date:` field on the page shows the day it is fetched, so it is never used.
- **Images** are hashed, not stored (`cache.json`, keyed by URL). An image whose SHA1 the wiki already holds, or that a page already in the plan uploads, is reused; the rest are named `<page> - NN.<ext>` with the extension of the sniffed type and each character MediaWiki forbids in a file name (`:`, `/`, `\` and those no title may hold) replaced by a lookalike, and a name the wiki already holds (a file with other bytes) sends the report to review. An image RSI answers with 404 is left out of the page and listed under the page's `missingImages`. Every body image renders as a thumb with no fixed size, `[[File:NAME|thumb|center]]`, or with `|CAPTION` when it carries one. RSI sometimes shows the same image twice on a page (a section header repeated further down); the page keeps only the first appearance, by resolved file name, and drops the rest. A dropped repeat's caption moves to the kept appearance when that one has none; two appearances whose captions both hold text and differ are both kept rather than losing one. An upload's file page credits `imageAuthor` (Cloud Imperium Games), except when the image's caption is wholly a community credit (case-insensitive `image by X`), which sets `author=` to X instead; a reused file's page is never touched.
- **Links** go to the first case-exact mention per section of a title in `linkCategories`, or of an `aliases` term, skipping disambiguation pages, the `stoplist`, a title with a parenthetical, a title under four characters, and single words the reports also use in lower case. A term never links inside a mention of a longer term (an alias such as `Hurston Dynamics` keeps `Hurston` from linking the planet there) or inside a `noLink` phrase, a name used in another sense (`Vulcan (G12)` is the graphics API, not the ship).

## Review reasons

| Reason | Meaning |
|---|---|
| `fetch-or-parse` | RSI's page or fragment could not be fetched, its layout was not recognised, or the API has no record of a report RSI's series lists |
| `title-exists` | the page name is taken by a page that does not store this RSI number, or an earlier report of the same run has the same page name, or (under `-refresh`) the wiki stores this RSI number on another page, which `detail` names |
| `no-date` | neither RSI's listing, the API nor the Wayback Machine dates the report, or the Wayback lookup failed; `detail` says which |
| `images` | an image could not be downloaded (other than a 404), is not an image, or its upload name is taken on the wiki by a different file |
| `api-text` | the API text has under half the page body's words; add the id to `apiTextAccepted` once the page is checked against RSI |
| `fidelity` | API text lines are missing from the page; `detail` lists them |

Accept a review entry for good by adding its id to `knownReview`, which keeps it out of `-diff`'s exit status.

## Output

`-diff` lists each page it would create (RSI number and page name), then the counts, and exits 1 while a page is missing or a review entry is not in `knownReview`. A plan with more creations than `-max-create` (default 10; a monthly run creates one or two) is written to `plan.rejected.json` only, leaving `plan.json` and `pages/` as the last run within the cap wrote them; the run exits 2.

`-refresh` re-plans a report the wiki already has, so its page can be regenerated with the current converter. It is only valid with `-only` and a non-default `-out`, the same rule `-only` alone already has. A listed id plans even though a wiki page already stores its RSI number, as long as that page has the title the report converts to; when the wiki stores the number on another title, the report goes to review as `title-exists`. Its `create` entry carries `"refresh": true`, so a publisher updates the existing page instead of creating a new one. Image planning is unchanged: files the page already holds resolve as reuse by SHA1, same as any other run.

## Another series

What the converter matches on is in `config.json`: the series slug, the title search and filter (`titleQuery`, `titlePattern`), page naming (`renames`), the greeting and sign-off (`greetingPattern`, `signOffPattern`), the infobox and file-page values, the link vocabulary, and the review and date exceptions. A second series needs its own config, passed with `-config`, and its own `-out`, since the default holds the monthly plan. The parsers have only been checked against monthly reports: the classic layout's studio sections and `Conclusion` block, and the fragment layout's emphasis article, are that series' shapes, so read a second series' first plan against RSI's pages before publishing it.
