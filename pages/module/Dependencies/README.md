# Module:Dependencies

The folded Technical details panel on module and template pages: which pages use the page, what it uses, and the functions a module defines.

Module:Documentation shows it on every documented module and template, and [MediaWiki:Scribunto-doc-page-does-not-exist](https://starcitizen.tools/MediaWiki:Scribunto-doc-page-does-not-exist) on a module with no `/doc`.

## For module editors

### API

Each page's row lives in the `dependencies` table of [Extension:Bucket](https://www.mediawiki.org/wiki/Extension:Bucket), schema `Bucket:Dependencies`, generated by `mise run bucket:schemas` from `properties.json`, registered in `Module:BucketQuery/manifests.json`.

- `panel(options) → string`: the panel followed by the page's categories, or the categories alone when the panel would be empty. Writes the page's row when the render is the page itself.

  | Field | Type | Default | Meaning |
  |---|---|---|---|
  | `page` | string | the current page | The page to describe. A `/doc` page describes the page it documents. |
  | `addCategories` | boolean or string | true, except on a `/doc` render | Whether to add the categories below. |
  | `sources` | list of `{ label, text }` | none | A Source row above the other rows, one line per entry's `text` (wikitext), with each `label` (plain text) leading the folded header's facts. Module:Documentation passes the page's wiki-tools and Wikipedia origins. |

- `main(frame)`: `panel()` for the current page, as `{{#invoke:Dependencies|main}}`.
- With categories on, a template with at least one invoke joins `[[Category:Lua-based templates]]`, a module that requires `strict` joins `[[Category:Strict mode modules]]`, and a module nothing invokes, requires, or loads joins `[[Category:Unused modules]]`.
- The functions come from [Module:Module toc](https://starcitizen.tools/Module:Module_toc).

### Gotchas

- The folded header sits inside `<summary>`, so it holds plain text only: a link there would be followed instead of opening the panel.
- A page writes its row only while rendering itself: never from its `/doc`, or a title containing `/sandbox` or `/testcases`, or starting with `Sandbox/`, in either namespace. Such a page is never flagged unused. A module's Used by row reads other pages' rows when the module's own page renders, so a new dependent appears after that page is next re-parsed.
- Only literal module names are stored. A dynamic `require('Module:X/' .. name)` is shown as `Module:X/…` and stored nowhere.
- A template that never shows `{{Documentation}}` writes no row, so the modules it invokes do not list it; a module whose `/doc` never shows it writes no row either.
- Stylesheet pages show no panel, so a stylesheet's users are listed on the page that owns it: `Module:Icon` lists who loads `Module:Icon/styles.css` under Styles used by. Only a `/styles.css` subpage has an owner. Loading a module's stylesheet does not use its code: a module whose only users load its stylesheet is still unused.
- When the Bucket lookup fails, a module's Used by row says the list is unavailable, and the module is not flagged unused.
