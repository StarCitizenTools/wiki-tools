# commlinks

Plans the pages of one RSI Comm-Link series or channel that the wiki is missing; `config.json` configures the monthly reports, `config.chairman.json` the From the Chairman letters, `config.serialized-fiction.json` the Serialized Fiction channel's stories and `config.portfolio.json` the Portfolio articles. See [`../../README.md`](../../README.md) for how tools run; this file covers what this one decides and why.

## What it plans

- **Discovery** is RSI's own listing, of a series (`series` in the config) or of a channel (`channel`), plus the Star Citizen Wiki API's title search (`titleQuery`, kept when `titlePattern` matches) or, with `apiChannel`, every comm-link the API files under that channel. Neither source is complete on its own (the API files three Serialized Fiction stories under "Feedback"): a report that either source finds is a candidate, and `plan.json` lists under `discoveryDisagreements` every report only one source found. When the API answers 404 for a report only RSI lists, the API has no record of it yet, and the report goes to review rather than stopping the run; a listing with no reports stops it, and so does an `apiChannel` the API files nothing under (the API answers a misspelt channel with an empty list). A candidate is missing when no page's `{{CommLink}}` `url` carries its RSI number (the `comm_link` Bucket table).
- **Body text** comes from RSI's HTML: the classic layout, or a Vue shell whose body is a separate fragment named by `const s3Url`. The layout follows the page, not its date: the reports moved to fragments in October 2021, the stories kept the classic body into 2024. The API's plain text is only the check: every API line must appear in the generated page, and the API text must have at least half the words of the page body (file lines and template calls left out), since an API text the API has not finished scraping checks only part of the page. `apiTextAccepted` lists reports a person has read against RSI's page, which pass the word check. Three API artefacts pass on their own: a line the API glues across page blocks in page order (a paragraph run into the sign-off past the Conclusion title and an image, or a row of captioned images run into the next paragraph, a captioned image's block being its caption); a line made up only of pieces of the page's image captions (a credit's intro such as "Image by" and a name), which the API runs together without spaces; and a line that lacks the page's dollar amounts, since the API drops `$` and up to two digits (`$48 million` becomes ` million`, `$100 million` `0 million`). A gallery's text is its captions, its own and each slide's, read like a thumb's caption. `fidelityIgnore` lists the other accepted API lines.
- **Media, polls and signatures**: a classic page's header block (`content-block2`) can hold an image, a slideshow, or a poll, which becomes its options with their share of the vote and the vote count; the poll's question is kept only when it is not its section's title. A slideshow, classic or fragment, becomes one `<gallery>`: a caption every slide shares (a fragment slideshow's title) is the gallery's `caption=`, given once, and otherwise each slide keeps its own. A fragment banner or slideshow whose JSON does not parse sends the report to review as `fetch-or-parse`. In a fragment, a trailer becomes a YouTube embed, the author block becomes the signature (name and role), and a banner that shows a paragraph (a pull-quote) becomes text; a banner's title is decoration.
- **Headings** in a body with `noSections` (a story) are bold text: RSI draws a writer's note, a script's scene headings and dialogue, and THE END as headings, and no bold line is a subsection title. With `byline`, a classic page's header subtitle that names the author ("By: Autumn Kalquist") opens the body; with `sceneBreaks`, a horizontal rule, a story's scene break, is kept as `----` (none first, last or twice in a row), otherwise a rule is dropped. Without `noSections`, headings are RSI's own, plus a bold line standing alone before more text, which becomes a subsection heading one level below the section's. A bold line is never a heading when it holds a colon (an addressee line such as `TO: SQUADRON 42 RECRUITS`), belongs to the closing emphasis article (a fragment report's last article, bold throughout; an emphasis article before it is a boxed section, converted as any other), or matches `greetingPattern` or `signOffPattern`. The same two patterns turn a classic heading into bold text: with `introHeadings`, whose series marks its intro with headings, only an intro heading (an `h1`, or a heading inside `variant-block`); without it, a heading at any level, and `variant-block` is only styling. In a fragment report `signOffPattern` turns the sign-off heading and every later heading of its article bold. A classic page's first title block is the page title, not a section, when it matches the report's title or `titlePattern`. With `studioSections`, a classic page with another title block than its own and `Conclusion` has one section per studio (the monthly reports to August 2018): a prose `h1` there is the studio's name, dropped or taken as the section title when it names the studio more fully, and prose headings sit one level lower. Without it, a prose `h1` that does not repeat its section's title is text.
- **Page names** are the RSI title after the first `renames` pattern that matches, with `: ` turned into ` - `. A name `datedTitlePattern` matches (a bare "Letter from the Chairman", which many letters share) takes ` - ` and the publication date, so the date is found before any name is checked or used; such a report with no date goes to review as `no-date`. When a classic page's own title block names a subject that bare title lacks ("Note from the Chairman: Dual Universe" listed as "Note from the Chairman"), the block is the report's title instead: the infobox shows it, and the page is named from it with no date.
- **Series**, the infobox's, is `infoboxSeries` for every report, or with `seriesFromReport` each report's API series label, renamed through `seriesRename` (the API calls one arc "Second Run"). A label in `standaloneSeries` names no arc ("News Update", "None"), so the report takes the title without its closing part marker (`(Part 1)`, `: Part One`, or `Act` and a number), or the whole title for a story in one part. The series names the page's category and its previous and next pages, so `plan.json` records it per page.
- **Dates** come, in order, from RSI's listing, whose `Posted:` value is the publication time for older items (`dateSource: "rsi"`; recent items show only an age such as "3 weeks ago"); else the API's `created_at`, unless it is one of `apiIngestDates` (days the API imported reports in bulk) or later than the first Wayback Machine capture of the RSI page (`"api"`); else that capture's UTC day (`"wayback"`). RSI's own `Date:` field on the page shows the day it is fetched, so it is never used.
- **Images** are hashed, not stored (`cache.json`, keyed by URL). An image whose SHA1 the wiki already holds, or that a page already in the plan uploads, is reused; the rest are named `<page> - NN.<ext>` with the extension of the sniffed type and each character MediaWiki forbids in a file name (`:`, `/`, `\` and those no title may hold) replaced by a lookalike, and a name the wiki already holds (a file with other bytes) sends the report to review. An image RSI answers with 404 is left out of the page and listed under the page's `missingImages`. Every body image outside a slideshow renders as a thumb with no fixed size, `[[File:NAME|thumb|center]]`, or with `|CAPTION` when it carries one. RSI sometimes shows the same image twice on a page (a section header repeated further down); the page keeps only the first appearance, by resolved file name, whether alone or a gallery's slide, and drops the rest. A dropped repeat's caption moves to the kept appearance when that one has none; two appearances whose captions both hold text and differ are both kept rather than losing one. An upload's file page credits `imageAuthor` (Cloud Imperium Games), except when the image's caption is a community credit (case-insensitive `image by X` or `screenshot by X`), the whole caption or its last clause after `; `, which sets `author=` to X instead; a reused file's page is never touched.
- **Links** go to the first case-exact mention per section of a title in `linkCategories`, or of an `aliases` term, skipping disambiguation pages, the `stoplist`, a title with a parenthetical, a title under four characters, and single words the reports also use in lower case. A term never links inside a mention of a longer term (an alias such as `Hurston Dynamics` keeps `Hurston` from linking the planet there) or inside a `noLink` phrase, a name used in another sense (`Vulcan (G12)` is the graphics API, not the ship).

## Review reasons

| Reason | Meaning |
|---|---|
| `fetch-or-parse` | RSI's page or fragment could not be fetched, its layout was not recognised, or the API has no record of a report RSI's listing names |
| `title-exists` | the page name is taken by a page that does not store this RSI number, or an earlier report of the same run has the same page name, or (under `-refresh`) the wiki stores this RSI number on another page, which `detail` names |
| `no-date` | neither RSI's listing, the API nor the Wayback Machine dates the report, or the Wayback lookup failed; `detail` says which |
| `images` | an image could not be downloaded (other than a 404), is not an image, or its upload name is taken on the wiki by a different file |
| `api-text` | the API text has under half the page body's words; add the id to `apiTextAccepted` once the page is checked against RSI |
| `fidelity` | API text lines are missing from the page; `detail` lists them |

Accept a review entry for good by adding its id to `knownReview`, which keeps it out of `-diff`'s exit status.

## Output

`-out` defaults to `out/commlinks` for `config.json` and to `out/commlinks-NAME` for `config.NAME.json`, so each series keeps its own plan, pages and cache; `mise run commlinks:chairman` and `mise run commlinks:chairman:diff` run the letters, `mise run commlinks:serialized-fiction` and `commlinks:serialized-fiction:diff` the stories, `mise run commlinks:portfolio` and `commlinks:portfolio:diff` the Portfolio articles.

`-diff` lists each page it would create (RSI number and page name), then the counts, and exits 1 while a page is missing or a review entry is not in `knownReview`. A plan with more creations than `-max-create` (default 10; a monthly run creates one or two) is written to `plan.rejected.json` only, leaving `plan.json` and `pages/` as the last run within the cap wrote them; the run exits 2.

`-refresh` re-plans a report the wiki already has, so its page can be regenerated with the current converter. It is only valid with `-only` and an `-out` other than any series' default (that of every `config*.json` beside the config), the same rule `-only` alone already has. A listed id plans even though a wiki page already stores its RSI number, as long as that page has the title the report converts to; when the wiki stores the number on another title, the report goes to review as `title-exists`. Its `create` entry carries `"refresh": true`, so a publisher updates the existing page instead of creating a new one. Image planning is unchanged: files the page already holds resolve as reuse by SHA1, same as any other run.

## Another series

What the converter matches on is in the config: the series or channel slug, the API's title search and filter (`titleQuery`, `titlePattern`) or channel (`apiChannel`), page naming (`renames`, `datedTitlePattern`), the greeting and sign-off (`greetingPattern`, `signOffPattern`, required unless `noSections`, which never reads them), the classic layout's monthly-report shapes (`studioSections`, `introHeadings`), a story's shapes (`noSections`, `sceneBreaks`, `byline`), the infobox series (`infoboxSeries`, or `seriesFromReport` with `standaloneSeries` and `seriesRename`) and the other infobox and file-page values, the link vocabulary, and the review and date exceptions. An unknown key stops the run. Another series needs its own `config.NAME.json`, passed with `-config`; its plan goes to `out/commlinks-NAME`. The parsers have been checked against the monthly reports, the letters, the stories and the Portfolio articles only (the articles read as stories do, with `noSections`, since RSI styles their section titles as headings and the wiki's Portfolio pages carry them as bold lines): the classic studio sections and `Conclusion` block and the fragment emphasis article are the reports' shapes, polls, header slideshows and the fragment's author block, trailers and banner quotes the letters', and heading-styled prose, rule scene breaks and header bylines the stories', so read a new series' first plan against RSI's pages before publishing it.
